uniqush-push — FCM demo

Get an FCM registration token, subscribe it to uniqush, then push to it.

1. Get a registration token

FCM issues registration tokens to browsers as well as to Android apps, and the HTTP v1 send API treats them identically — same token target, same request, same code path in srv/fcm. So a browser is enough to verify the server side; an Android device only adds the platform-specific android block.

Requires localhost or HTTPS, and a browser with FCM web push support (Chrome, Edge, Firefox). Safari on macOS needs the site installed as a web app first.

Or paste a token from an Android device

From FirebaseMessaging.getInstance().getToken() in an app built against this same Firebase project. A token from a different project fails with SENDER_ID_MISMATCH, which uniqush treats as a permanent failure and unsubscribes.

2. Push

Sent as a data message, not a notification one, so what appears on screen is uniqush's payload having survived the round trip rather than something the browser rendered by itself. A message arriving while this tab is focused is handled by the page; one arriving while it is not is handled by the service worker. Both display a notification, and the log below says which path it took.
